# Why Not Futures?
Scala's Future is not RT
- it eagerly evaluates the computation upon creation
- runs it asynchronously on a background thread pool
- No guarantee in the order of execution if dealing with more than one Future, resulting in different results

Reusing same value  Reuses the same result          Re-executes when run
